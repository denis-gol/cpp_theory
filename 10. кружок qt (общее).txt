РАЗДЕЛ 0. РОАДМАП ИЗУЧЕНИЯ QT (Роадмап промышленной разработки на Qt 6)

Шаг 1. Управление данными в памяти (Базис Qt Core)
 - Строковый движок: Архитектура QString (UTF-16), технологии Copy-on-Write (Implicit Sharing) и предотвращение скрытого детачмента через константный API (.at()). Сборка строк через QString::arg() и оптимизация аллокаций памяти в Qt 6.
 - Универсальные контейнеры: Работа с QVariant, регистрация пользовательских структур в мета-системе через Q_DECLARE_METATYPE.
 - Умные указатели Qt: Управление временем жизни QObject (QPointer, QScopedPointer). Запрет использования std::shared_ptr для виджетов.

Шаг 2. Архитектура метаобъектов (MOS)
 - Под капотом MOC: Как утилита Meta-Object Compiler превращает макрос Q_OBJECT, ключевые слова signals: и slots: в чистый C++ код. Директива CMAKE_AUTOMOC в CMake.
 - Сигналы и слоты: Старый синтаксис (макросы SIGNAL/SLOT) против современного синтаксиса Qt 5/6 на указателях со строгой проверкой типов на этапе компиляции.
 - Особенности связей: Лямбда-выражения в качестве слотов. Типы соединений (Qt::DirectConnection, Qt::QueuedConnection) — фундамент для многопоточности.

Шаг 3. Жизненный цикл GUI и управление геометрией
 - Event Loop (Цикл обработки событий): Как QApplication::exec() крутит бесконечный цикл. Анатомия QEvent, переопределение методов event() и фильтры событий (eventFilter).
 - Иерархия владения: Дерево объектов QObject (родитель-потомок) и автоматическое освобождение памяти кучи.
 - Менеджеры компоновки (Layouts): Принципы работы QVBoxLayout, QHBoxLayout, QGridLayout. Различия между размещением элементов на стеке (опасность RAII для GUI) и динамическим выделением через new во владение Layout.

Шаг 4. Промышленная архитектура Model-View
 - Widget-based подход: Почему QTableWidget и QListWidget не используются в серьезных проектах (проблема дублирования данных и жесткой связанности).
 - Разделение логики: Изучение триады Model-View-Controller в Qt. Интерфейсы QAbstractItemModel, QAbstractTableModel.
 - Отображение и кастомизация: Стандартные представления (QTableView, QListView). Создание кастомных делегатов (QStyledItemDelegate) для отрисовки ячеек и прокси-модели (QSortFilterProxyModel) для фильтрации данных без изменения самой модели.

Шаг 5. Сетевое взаимодействие и Многопоточность
 - Асинхронная сеть: Работа с QNetworkAccessManager, QNetworkReply, QNetworkRequest. Обработка REST API и парсинг JSON через QJsonDocument.
 - Потоки в Qt: Правильный паттерн работы с QThread (архитектура Worker-object + moveToThread) вместо опасного наследования от QThread::run.
 - Параллельные вычисления: Высокоуровневая библиотека Qt Concurrent и класс QFuture.

Шаг 6. Современный интерфейс (QML & Qt Quick)
 - Декларативный GUI: Синтаксис языка QML, интеграция графических элементов и анимаций.
 - Мост между C++ и QML: Регистрация C++ классов в контексте QML (qmlRegisterType), передача данных через свойства Q_PROPERTY и обмен сигналами между тяжелой бизнес-логикой и легким UI.

РАЗДЕЛ 0-1. Временная оценка Роадмапа промышленной разработки на Qt 6

Шаг 1. Управление данными в памяти (Базис Qt Core)
 - Время на прохождение: 4 - 5 часов чистой практики.
 - Обоснование: Базовые принципы работы Copy-on-Write и матрешек памяти уже усвоены на низком уровне. Время требуется на фиксацию синтаксиса упаковки и распаковки метатипов в QVariant через Q_DECLARE_METATYPE, а также на изучение умных указателей QPointer и QScopedPointer. Дополнительно разбирается причина запрета использования std::shared_ptr для виджетов из-за конфликта с деревом владения Qt.

Шаг 2. Архитектура метаобъектов (MOS)
 - Время на прохождение: 5 - 6 часов.
 - Обоснование: С учетом опыта низкоуровневого анализа компилятора, фокус будет смещен на чтение сгенерированного утилитой кода в файле moc_mainwindow.cpp. Требуется увидеть, как сигналы превращаются в обычные методы, а слоты вызываются по индексам через массивы указателей. Изучение QueuedConnection заложит фундамент для понимания асинхронности в многопоточной среде. Разбирается автоматизация процесса через CMAKE_AUTOMOC.

Шаг 3. Жизненный цикл GUI и управление геометрией
 - Время на прохождение: 5 - 7 часов.
 - Обоснование: Анатомия Event Loop на базе бесконечного цикла QApplication::exec() уже понятна. Основное время уйдет на практическую реализацию кастомных фильтров событий через eventFilter() и переопределение метода event(). Будет детально изучено дерево объектов QObject и автоматическое освобождение памяти кучи. Практика включает работу с менеджерами компоновки (QVBoxLayout, QHBoxLayout, QGridLayout) исключительно через код без визуальных редакторов, с разбором опасности RAII для элементов интерфейса.

Шаг 4. Промышленная архитектура Model-View
 - Время на прохождение: 10 - 12 часов.
 - Обоснование: Это самый сложный и объемный архитектурный блок роадмапа. Разбирается, почему QTableWidget и QListWidget являются антипаттернами в серьезных проектах из-за дублирования данных. Изучается реализация триады MVC через интерфейсы QAbstractItemModel и QAbstractTableModel. Требуется написать несколько мини-проектов для освоения кастомных делегатов QStyledItemDelegate и прокси-моделей QSortFilterProxyModel для фильтрации и сортировки данных.

Шаг 5. Сетевое взаимодействие и Многопоточность
 - Время на прохождение: 6 - 8 часов.
 - Обоснование: Понимание контекстов и указателей позволит быстро освоить асинхронный сетевой стек (QNetworkAccessManager, QNetworkReply, QNetworkRequest) и парсинг JSON через QJsonDocument. Время уйдет на освоение правильного паттерна работы с QThread через архитектуру Worker-object и метод moveToThread вместо наследования от метода run. Также изучаются высокоуровневые вычисления через Qt Concurrent и класс QFuture.

Шаг 6. Современный интерфейс (QML & Qt Quick)
 - Время на прохождение: 8 - 10 часов.
 - Обоснование: Время требуется на адаптацию к декларативному синтаксису языка QML и логике работы его встроенной виртуальной машины JavaScript V4. Основной упор делается на создание архитектурного моста между C++ и QML. Разбирается регистрация классов через qmlRegisterType, передача данных через свойства Q_PROPERTY и организация обмена сигналами между тяжелой бизнес-логикой на C++ и легким UI на QML.

Итоговая оценка роадмапа
 - Общее время: 38 - 48 часов сфокусированной работы.
 - Сроки реализации: При темпе обучения 4 - 6 часов в неделю весь роадмап промышленной разработки закрывается за 2.5 - 3 месяца.

ИЕРАРХИЯ ЯДЕР ПРИЛОЖЕНИЯ

QCoreApplication --> QGuiApplication --> QApplication

QCoreApplication - Уровень «Без графики» (Консоль и Серверы)
    - Что делает: Инициализирует Event Loop, обрабатывает argv/argc, управляет таймерами (QTimer), 
        сокетами (QTcpSocket), потоками (QThread) и механизмами сигналов и слотов.
    - Когда использовать: консольное приложение, утилита командной строки, системный демон, бэкенд для сервера.

QGuiApplication - Уровень «Базовая графика» (QML и Мобильные ОС)
    - Что делает: подгружает графические драйверы, понимает, что такое экран, буфер кадра, отслеживает координаты 
        тачскрина/мыши, управляет окнами верхнего уровня (QWindow) и системными шрифтами.
    - Когда использовать: современное приложение на базе Qt Quick / QML.

QApplication - Уровень «Максимум» (Классический десктоп)
    - Что делает: добавляет сверху колоссальный пласт кода для поддержки модуля QtWidgets. Знает, что такое
        классическая кнопка, полоса прокрутки, как работают сложные компоновщики (Layouts), как отрисовывать 
        QMainWindow, меню и статус-бары. Подстраивает окно по текущий стиль ОС (шрифты, тема итд).
    - Когда использовать: классическое настольное (десктопное) приложение для Windows, macOS или Linux.


//--------------------------------------
QApplication
Главный управляющий центр всего приложения. Наследуется от QGuiApplication, который наследуется от QCoreApplication.
Создается в единственном экземпляре (Singleton).
Мост между программой на C++ и графической подсистемой операционной системы (Win, Linux, macOS).

Какие задачи выполняет app под капотом?
- Инициализация оконного движка - Qt связывается с Windows (через WinAPI), регистрирует классы окон, 
    инициализирует графические драйверы и подготавливает буферы для отрисовки.
- Сбор системных настроек - Программа считывает настройки ОС: текущую тему (темная/светлая), системные шрифты, 
    масштабирование экрана (DPI) и языковую локаль.
- Управление временем жизни окон - Объект app следит за всеми открытыми окнами верхнего уровня - при закрытии последнего
    закрывает программу.
- Подготовка Главного цикла событий (Event Loop): Строка QApplication app создает и настраивает этот цикл в памяти. 
    Сам же цикл запустится позже — на строке return app.exec();

В коде функции main строка с QApplication всегда обязана идти ДО создания любых графических объектов 
    (MainWindow w; или QWidget widget;) Иначе - крах (0xC0000602).



//--------------------------------------
Какие типы окон бывают в Qt?

1) Главные окна (QMainWindow)
    Продвинутый тип окон верхнего уровня, предназначенный для каркаса всего приложения. Они всегда «из коробки» 
    поддерживают панели меню, статус-бары и перетаскиваемые док-панели. Обычно в программе такое окно только одно.
2) Обычные окна / Виджеты (QWidget без родителя)
    Самостоятельное окно на рабочем столе.
3) Диалоговые окна (QDialog) - «Открыть файл», «Настройки», предупреждение «Сохранить изменения?»
    - Немодальное - Работают как обычные окна — можно переключиться обратно на главное окно, не закрывая диалог.
    - Модальное - окно намертво блокирует весь остальной интерфейс программы. Пользователь обязан нажать ОК или Отмена.
4) Окна-заставки (QSplashScreen)
    Особый тип графических окон без рамок, который появляется по центру экрана в первые секунды запуска тяжелых программ
    Выводит логотип, шкалу загрузки итд (CLion, Gothic II).

---
Уровни модальности

(setWindowModality()):
Qt::NonModal: Окно полностью независимо, ничего не блокирует (пример: панель поиска Ctrl+F).
Qt::WindowModal: Блокирует только то конкретное окно-предок, из которого было вызвано.
Qt::ApplicationModal: Намертво блокирует абсолютно все графические окна приложения.

---
Заставочные окна (Splash Screens): 
класс QSplashScreen. Обладают флагами: 
    - безрамочность (Qt::FramelessWindowHint), 
    - отображение поверх всех окон (Qt::WindowStaysOnTopHint), 
    - скрытие из панели задач (Qt::SplashScreen)
    - опциональная прозрачность (Qt::WA_TranslucentBackground). 

В потоке загрузки критически важен вызов QApplication::processEvents()

Графика

1) Виджеты (QWidget) - самая старая технология, воспроизводит визуально элементы ОС.
2) QML и Qt Quick - разработанное в Qt рисование элементов (лучше, динамичнее, плавнее итд).
3) Qt Graphics View Framework (QGraphicsView, QGraphicsScene)
    Идеальный инструмент для создания 2D-графики, интерактивных карт, схем или простых 2D-игр.
    Создаем сцену (QGraphicsScene), накидываем независимые объекты.
    Система следит за кликами по ним, умеет их масштабировать, вращать и группировать.
4) Прямая 2D-отрисовка на холсте (QPainter)
    Позволяет нарисовать что-то вручную (график функций, кастомную круговую диаграмму, сложный узор).
    Рисуется буквально командами: painter.drawEllipse(...), painter.drawLine(...).
5) Трехмерная графика (3D)
    - Qt 3D — высокоуровневый C++/QML движок для создания полноценных 3D-сцен, симуляций и визуализаций.
    - Qt Quick 3D — простой способ добавить 3D-элементы (3D модель автомобиля) внутрь плоского 2D-интерфейса на QML.
    - Интеграция с OpenGL/Vulkan (QOpenGLWidget) — низкоуровневый доступ к видеокарте для своего игрового движка.

Что такое «Формы»?
Файл визуального дизайна интерфейса. Способ работы с формами зависит от выбранной технологии:
- Widget (.ui файлы) - Рисуем интерфейс в Qt Designer. На выходе получаем файл mainwindow.ui (внутри XML-текст), 
    который утилита uic перед компиляцией превращает в C++ код ui_mainwindow.h
- Для QML (.qml файлы) - Интерфейс пишется в текстовых файлах .qml.
    Используется визуальный редактор (Qt Quick Designer), либо прога Qt Design Studio (генерирует готовый QML-код)

---
QWidget

Секрет фирмы: Виджеты привязаны к операционной системе, но они не используют встроенные элементы (контролы) ОС напрямую. 
    Они их ИМИТИРУЮТ - получают текущие стили ОС (класс QStyle) и рисуют попиксельно элементы, полностью аналогичные ОС.
    Это нагружает ЦП (а не VideoCard), вызывает полную перерисовку при изменении, трудно кастомизировать.

---
QML и Qt Quick
    Появились как замена тяжелым виджетам. Вся нагрузка - ложится на VC (GPU).
    Интерфейс выглядит абсолютно одинаково и на Windows, и на Android, и на экране бортового компьютера автомобиля.

Движок QML содержит внутри себя полноценную встроенную виртуальную машину JavaScript (собственный высокооптимизированный 
    движок, который называется V4, собранный инженерами Qt под нужны интерфейса). Он сильно быстрее V8 (Chrome).
    JS в QML изолирован и предназначен строго для обслуживания интерфейса (сделать математический расчет координат, 
    склеить строки для текста кнопки, отфильтровать элементы в списке, переключить состояние анимации).
    Остальные задачи (сходить в БД, прочитать файл) передаются в C++ (м вызвать функцию прямо из JS - onClicked: {...})

QML (Qt Meta-object Language) - декларативный язык программирования. Визуально похож на JSON или CSS. Описываем 
    структуру интерфейса словами. Также внутри QML можно писать логику на JavaScript.
Qt Quick - стандартная библиотека (модуль) для QML. Содержит готовые визуальные элементы: кнопки, ползунки, анимации, 
    механизмы разметки и трансформаций.

---
Объединение виджетов и QML.


QtWidgets - идеален для тяжелых интерфейсов - имеет мощные, готовые и очень быстрые таблицы (QTableView), деревья данных,
    сложные инженерные док-панели (QDockWidget) и менеджеры окон.
QML - идеален для визуализации и мультимедиа - анимированный красивый плеер, интерактивная промо-страница,
    кастомная диаграмма, которая плавно реагирует на движения мыши — это пишется на QML за пару часов.

Существуют специальные «мосты» (классы-контейнеры), которые позволяют бесшовно встраивать QML-элементы внутрь 
    классических виджетов и наоборот.

Концепция пирога рантаймов (Runtime Layering)

Слой 1. Рантайм Qt (Высший уровень)
    Фреймворк Qt (все эти .dll файлы из папки ucrt64/bin) полностью изолируют от нюансов конкретной ОС.
    Берет на себя управление памятью (автоудаление виджетов через иерархию родителей), трансляцию кликов мыши через 
    собственную мета-систему сигналов и слотов, динамическую компиляцию JavaScript (через движок V4 в QML)
    и отрисовку пикселей. Программа «думает», что мир состоит только из объектов Qt.

Слой 2. Рантайм C++ / Рантайм компилятора (Средний уровень)
    Qt написан на чистом C++, используется рантайм C++ (библиотеки компилятора GCC/MinGW UCRT64, такие как 
    libstdc++-6.dll или libwinpthread-1.dll

Слой 3. Системный рантайм ОС (UCRT)
    Системный рантайм самой Windows. Буквы UCRT расшифровываются как Universal C Runtime (Универсальный рантайм Си)
    Самый базовый программный слой в Windows 10/11. Именно он предоставляет функции для открытия файлов на жестком диске,
    выделения физических страниц оперативной памяти у ядра ОС, вывода текста в черное окно консоли и сетевых запросов.
    Рантайм C++ и Qt вызывают функции из UCRT, а UCRT переводит их в системные вызовы напрямую к ядру Windows.

Прочие основные элементы Qt

1) Мета-объектная система (Связующий клей). Работает благодаря утилите MOC (Meta-Object Compiler) и макросу Q_OBJECT
    - Сигналы и Слоты: Механизм для безопасного общения объектов между собой - кнопка кричит, функция-слот ее слышит.
    - Рефлексия (Интроспекция) - можно узнать какие у класса есть методы, свойства, как он называется.
    - Динамические свойства - можно на лету добавить объекту новую переменную (свойство) прямо во время работы программы
2) Кроссплатформенная абстракция ОС (Модуль Qt Core)
    - Файловая система (QFile, QDir, QFileInfo) - не нужно думать про пути (/ или \)
    - Потоки и Асинхронность (QThread, QThreadPool, QtConcurrent)
    - Таймеры (QTimer): позволяют выполнять код через заданные промежутки времени (для анимаций, опроса датчиков итд).
3) Сетевой стек (Модуль Qt Network)
    - Высокий уровень (QNetworkAccessManager): Отправка HTTP/HTTPS (GET, POST), скачивание файлов, REST API сайтов. 
        Сам управляет куками (cookies), кэшем и прокси-серверами.
    - Низкий уровень (QTcpSocket, QUdpSocket): Для создания собственных сетевых протоколов, чатов, пиринговых сетей 
        или обмена данными с физическими устройствами по TCP/UDP.
4) Работа с данными (Модули Sql и Xml/Json)
    - Qt SQL: Единый интерфейс для работы с базами данных. Одинаково работает с SQLite, PostgreSQL или MySQL.
        Есть абстрактные методы, а можно делать прямые запросы для передачи в БД напрямую (класс QSqlQuery).
    - Парсеры (QJsonDocument, QXmlStreamReader): Быстрые модули для сохранения настроек программы или обмена данными 
        с сервером в форматах JSON и XML.
5) Контейнеры данных (Аналог STL, но оптимизированный)
    Собственные альтернативные контейнеры: QString, QList, QMap, QHash
    - намертво интегрированы со всей графикой Qt.
    - используют технологию Implicit Sharing (Copy-on-Write)
    - QString из коробки идеально поддерживает кодировку UTF-16 (кошмар с кириллицей на разных ОС)

Главный цикл событий (Event Loop)

Запускается так: return app.exec();
Под капотом это бесконечный цикл while, который крутится в рамках главного потока приложения (Main Thread / UI Thread).
Выглядит примерно так:
int QEventLoop::exec() {
    while (!m_exitRequested) { // Крутимся, пока не вызвали quit()
        // 1. Спим и ждем системное сообщение от ОС
        MSG msg = waitForSystemMessage(); 
        
        // 2. Превращаем системное сообщение в объект QEvent
        QEvent* event = translateSystemMessage(msg);
        
        // 3. Отправляем событие конкретному виджету-получателю
        QCoreApplication::notify(event->receiver(), event);
        
        delete event;
    }
    return m_exitCode;
}

Главная фишка Event Loop - не нагружает процессор на 100%, пока программа бездействует. 
Если пользователь не двигает мышь и не жмет кнопки, цикл не крутится впустую.

1) Ожидание (Блокировка потока): Функция ожидания (waitForSystemMessage) отправляет поток приложения в режим сна.
2) Пробуждение: Как только пользователь шевельнул мышкой над окном, контроллер прерываний сообщает ОС о событии. 
    Windows формирует сообщение (например, WM_MOUSEMOVE) и пихает его в системную очередь сообщений класса окон. 
    Поток Qt мгновенно просыпается.
3) Очередь событий и доставка (QCoreApplication::postEvent)
    Внутри рантайма Qt события делятся на два типа по способу их доставки:
    - Синхронные события (QCoreApplication::sendEvent): Отправляются «в лоб», минуя очередь событий. Qt напрямую 
        вызывает функцию обработки события у виджета. Программа ждет, пока виджет отработает, и только потом идет дальше.
    - Асинхронные события (QCoreApplication::postEvent): Помещаются в Очередь событий (Event Queue) — динамический 
        список в куче. Event Loop последовательно берет события из этой очереди по принципу FIFO.
4) Роль Event Loop в механизме Сигналов и Слотов
    Для объектов в одном потоке, вызов сигнала — это просто прямой вызов функции-слота.
    Для многопоточных приложений используются Соединения-в-очереди (Queued Connections) между разными потоками (#DIGDEEP)
5) Почему падает или зависает интерфейс?
    - Зависание («Приложение не отвечает»): Если внутри MainWindow запустить тяжелый мат. цикл или долгий сетевой запрос 
        на 10 секунд, поток окажется занят вычислением. До строки GetMessage (опроса ОС) управление не дойдет. 
        Очередь событий забьется, Windows поймет, что программа не забирает сообщения о кликах мыши, и сделает окно 
        блеклым, добавив надпись «Не отвечает».
    - Если фоновый поток попытается напрямую изменить текст виджета, минуя Event Loop и очередь событий, он ворвется 
        в память графического движка в тот момент, когда главный поток ее перерисовывает. Произойдет повреждение кучи.

---
Подробнее про очередь событий и доставку:

Способ доставки события (напрямую через sendEvent или асинхронно через очередь postEvent) определяется тремя факторами: 
- типом (природой) самого события, 
- типом соединения в механизме сигналов и слотов
- архитектурными флагами, которые прогер выставляет в коде.

1) Архитектурное разделение по типу события (Рантайм Qt):
    - Асинхронная доставка (через Очередь событий / postEvent): Сюда попадают все события, которые генерируются внешним 
        миром (операционной системой или оборудованием).
        Пример: Движение мыши (QMouseEvent), нажатие клавиши (QKeyEvent), тиканье таймера (QTimerEvent).
        Событий огромное количество, поэтому чтобы не нагружать программу они падают асинхронно.
    - Синхронная доставка (напрямую / sendEvent): Сюда относятся события, которые генерируются внутренней логикой 
        самого приложения и требуют немедленного ответа.
        Пример: Событие закрытия окна (QCloseEvent), событие изменения геометрии виджета (QResizeEvent), или системная 
        команда немедленной перерисовки окна (QPaintEvent при вызове repaint()).
        Внутренние события нужно обработать как можно быстрее, иначе окно мб уничтожено раньше, чем дошла очередь.

2) Автоматический выбор на основе потоков (Сигналы и Слоты)
    - Объекты в одном потоке (Qt::DirectConnection) - синхронно.
    - Объекты в разных потоках (Qt::QueuedConnection) - асинхронно, в очередь главн потока QCoreApplication::postEvent

3) Явный выбор программиста (Управление памятью и временем)
    При создании кастомного события (наследуясь от QEvent), кодер обязан руками выбрать метод доставки. 
    Этот выбор жестко завязан на управление памятью C++:
    - Синхронно (QCoreApplication::sendEvent()): Событие должно создаваться на стеке.
    - Асинхронно (QCoreApplication::postEvent()): Событие должно создаваться строго в куче через new.

Концепция Implicit Sharing / Copy-on-Write / COW
(скрытое разделение данных / копирование при записи)
    Фундаментальная оптимизация управления памятью, применяемая в рантайме Qt Core для всех тяжелых контейнеров 
    (QString, QList, QMap, QHash, QImage). Объекты совместно используют один и тот же блок памяти в куче до тех пор, 
    пока один из них не попытается этот блок модифицировать.

На примере объекта QString (внутри QStringData) - есть счетчик ссылок на объект. При создании он равен 1.
Это поле ref является атомарным целым числом (QAtomicInt), завязано на команды LOCK процессора и потокобезопасно.
При копировании (QString s2 = s1;) он станет равным 2, итд.
До тех пока пока не будет попытки изменить s2 фактически пользуемся s1. Как только пытаемся менять, проверка:
if (d->ref.loadRelaxed() > 1) { 
    detach(); // Скрытое физическое отделение данных!
}
Создается новый объект и применяются изменения - это и есть "Копирование при записи"


---
Разница поведения: Константные и Неконстантные методы

1) Константные методы (.length(), .isEmpty(), .at(), .contains()): 
    Гарантируют, что данные не будут изменены. При их вызове проверка счетчика ссылок ref не производится, 
    детачмент никогда не вызывается. Сколько бы объектов ни разделяли одну память, чтение всегда происходит мгновенно 
    и без выделения памяти.
2) Неконстантные методы (.clear(), .replace(), operator[]): 
    Всегда проверяют счетчик ссылок. Если ref > 1, рантайм немедленно производит глубокое копирование (выделение 
    новой памяти), даже если в итоге вы не изменили данные (например, просто обратились по индексу через operator[].

ВАЖНО!
Вместо: QChar c = text[i];    // неконстантный operator[], вызовет копирование (в цикле особенно "весело")
Пишем : QChar c = text.at(i); // константный метод, данные не копируются

Прим:
В C++11+ технология Copy-on-Write в стандартных строках std::string официально запрещена - атомики (ref) заставляют 
    ядра процессора сбрасывать кэши и синхронизировать шину данных. Потери больше выигрыша.
    Также добавили: SSO (оптимизация малых строк), MoveSemantics.

QString

Главный и самый мощный класс модуля Qt Core, предназначенный для хранения, обработки и манипуляции текстовыми строками.
Полноценный высокоуровневый инструмент, на котором держится весь графический интерфейс фреймворка Qt.

Главные задачи и архитектурные функции класса:
1) Родная поддержка Юникода (UTF-16)
    каждый символ является не байтом, а двухбайтным объектом класса QChar. Это гарантирует, что любая международная 
    кодировка (кириллица, иероглифы, эмодзи) поддерживается нативно.
    Метод length() всегда возвращает реальное количество букв в строке, а не количество занятых байт в памяти.
2) Экстремальная скорость через Implicit Sharing (Copy-on-Write)
3) Мощный встроенный API для манипуляций
    Класс заменяет собой десятки сторонних библиотек, предоставляя готовые методы для любых задач:
    - Поиск и замена: .contains(), .indexOf(), .replace(), регулярки
    - Очистка текста: .trimmed(), .toLower() / .toUpper()
    - Разбиение и склейка: .split(), .join()
    - Безопасная сборка строк: цепочки методов .arg() для безопасного форматирования данных.

Физически QString на стеке занимает всего 8 байт (на x64 архитектуре). Эти 8 байт представляют собой обычный сырой 
    указатель на скрытую структуру QStringData, расположенную в куче.

 СТЕК (8 байт)                    КУЧА (Выделенная память)
┌──────────────┐         ┌─────────────────────────────────────────────────────────┐
│  QString     │ ──────> │ QStringData (Служебный заголовок)                       │
└──────────────┘         │  - Счетчик ссылок (Reference Counter)                   │ <-- отвечает за Copy-on-Write
                         │  - Длина строки (Размер массива)                        │
                         │  - Зарезервированная память (Capacity)                  │
                         ├─────────────────────────────────────────────────────────┤
                         │ Массив символов QChar (Каждый элемент занимает 2 байта) │
                         │ [П][р][и][в][е][т][\0]                                  │
                         └─────────────────────────────────────────────────────────┘

QVariant 

Аналог std::any из современного C++, но глубоко интегрированный в Qt.
Контейнер для хранения всего (число, строку, дату, кастомный объект)

Внутри два ключевых элемента:
1) Сырые данные (буфер памяти): Сама порция данных (или указатель на них в куче, если объект тяжёлый).
2) Мета-информация (QMetaType): Идентификатор типа, который сейчас лежит внутри. Рантайм Qt всегда точно знает, 
    что именно упаковано в коробку.

QVariant box; // Коробка пока пустая (тип QMetaType::UnknownType)
    box = 42;                             // Теперь внутри int
    qDebug() << box.metaType().name();    // Выведет: "int"

    box = QDate::currentDate();           // Теперь внутри объект даты
    qDebug() << box.metaType().name();    // Выведет: "QDate"

примеры упаковки:
    QVariant v1 = 100;                 // Упаковали int
    QVariant v2 = QString("Hello");    // Упаковали строку Qt
    QVariant v3 = true;                // Упаковали bool

---
Извлечение данных (Распаковка)

Нельзя работать с данными внутри напрямую, сначала их нужно извлечь, это делается через получение типа:
    int number = v1.toInt();       // Достали int (number = 100)
    QString text = v2.toString();  // Достали строку
    bool boolean = v3.toBool();    // Достали флаг

Примитивы вернутся только при получении - bool, int, double, float. Все остальные методы .to... возвращают объект Q...
    (QString, QChar, QDate). 
Методы, получающие примитив принимают флаг на успешность toInt(&result). Если не получилось распаковать, то вернется 0:
    bool ok = false;
    int fail = v2.toInt(&ok); // ok станет равен false, fail вернет 0

Можно так:
    QVariant v1 = 100;   
    QString str = v1.toString();
    
Специализированные методы (toInt(), toString()) существуют только для базовых типов. Для всех остальных типов 
    (включая сложные объекты Qt или кастомные структуры) используется универсальный шаблонный метод .value<T>():
    QColor color = v1.value<QColor>(); // Пытаемся достать объект цвета из коробки
Этот метод работает строго по контракту типов компилятора: если запрашиваемый тип T в угловых скобках не совпадает 
    с ярлыком внутри QVariant и рантайм не знает правил их взаимного приведения, вернется пустой, сконструированный 
    по умолчанию объект типа T.
