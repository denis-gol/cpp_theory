ВЕРСИИ ЯЗЫКА

Современный стандарт:
- C11 (ISO/IEC 9899:2011) — Главный стандарт индустрии.
    Добавил в язык нативную поддержку многопоточности (<threads.h>, <atomic.h>), 
    статические утверждения (_Static_assert) и поддержку Юникода.
- C17 / C18 (ISO/IEC 9899:2018) — Это багфикс-релиз для C11.
    Нет новых фич, только исправления технических ошибок C11.
    Повсеместно используется в дистрибутивах Linux (включая код ядра и системных утилит).
- C23 (ISO/IEC 9899:2024) — Активно внедряемый стандарт.
    Поддержка в GCC/Clang уже практически полная.
    Добавлено: true-bool (true и false вместо 1 и 0), ключевое слово nullptr, атрибуты [[maybe_unused]] (как в C++), 
    стандартизировали инициализацию пустыми скобками {}.

Легаси живое (Индустриальный стандарт прошлого):
- C99 (ISO/IEC 9899:1999) — 
    Огромный пласт существующего софта, библиотек и старых ядер Linux/микроконтроллеров написан на нем.
    Подарил нам тип long long, комментарии через //, типы точного размера (int32_t, uint64_t из <stdint.h>) 
        и возможность объявлять переменные внутри цикла for(int i...).
    Нужно знать и уметь читать, так как в старых enterprise-проектах и сертифицированном софте 
        (авиация, космос, автопром) он будет жить еще десятилетиями.

Легаси мертвое:
- C89 / C90 (ANSI C / ISO C) - боль: объявления строго в самом начале функции. Нет for, типов uint32_t, bool
- K&R C (Код в стиле Кернигана и Ритчи, до 1989 года) — Музейный экспонат. Синтаксис полностью удален из языка.

#define

2 типа:
    - объектные (без параметров)
    - функциональные (с параметрами)

Строка директивы всегда жестко делится на следующие части:
    1. Директива препроцессора: Строго текст #define.
    2. Идентификатор (Имя макроса): То, что будем заменять. Пишется БЕЗ ПРОБЕЛОВ внутри. Если это макрос с параметрами, 
        то открывающая скобка (должна идти вплотную к имени (например, SQUARE(x)). Если поставить пробел SQUARE (x), 
        препроцессор подумает, что имя макроса — это SQUARE, а всё остальное — это текст для замены.
    3. Тело макроса (Строка замены): Всё, что идет после первого пробела (или пробельных символов) после Идентификатора 
        и до конца строки. Внутри тела пробелы разрешены в любом количестве.


Вариант 1: Объектный макрос (Простой)
         #define     MAX_SIZE      100 + 50
          (1)          (2)           (3)
        Директива     Имя       Тело (Текст замены, пробелы внутри разрешены)

Вариант 2: Функциональный макрос (С параметрами)
         #define     BOOL_STR(x)   ((x) ? "true" : "false")
          (1)            (2)                 (3)
        Директива   Имя+Параметры     Тело макроса (Весь остальной текст)
                    (БЕЗ пробела)


Правила для пробелов
1) Пробелы между 1 и 2, а также между 2 и 3: 
    Могут быть в любом количестве (один пробел, десять пробелов, знак табуляции \t).
2) Не должно быть пробелов в имени или имени+аргумент: ASDF (arg) (arg*arg) - ошибка, пробел между ASDF и (arg)
    Пробелы ВНУТРИ скобок (между аргументами) разрешены.
3) Пробел внутри тела (3): Сохраняется как есть.
4) Перенос строки: \n считается концом строки. Но можно переносить с помощью \ (Line Continuation Character)

Промышленный стандарт записи - тело пишут на второй строке:
    #define BOOL_DEF(x) \
        ((x) ? "true" : "false")

    
+------------------------------------+------------------------------------+-------------------------------------+
| Вариант синтаксиса                 | Шаблон / Пример                    | Во что превращается                 |
+------------------------------------+------------------------------------+-------------------------------------+
| 1. Объектный макрос (подстановка)  | #define ИМЯ значение               | Везде в коде слово "ИМЯ" заменяется |
|                                    | #define MAX_SIZE 100               | на кусок текста "значение".         |
+------------------------------------+------------------------------------+-------------------------------------+

|                                    | #define DEBUG_MODE                 | компиляции (`#ifdef`). Текст пустой |
+------------------------------------+------------------------------------+-------------------------------------+
| 3. Функциональный макрос           | #define ИМЯ(парам) тело            | Текстовая подстановка аргументов    |
|                                    | #define SQUARE(x) ((x) * (x))      | прямо в тело макроса.               |
+------------------------------------+------------------------------------+-------------------------------------+
| 4. Строковый оператор (#)          | #define TO_STR(x) #x               | Оборачивает переданный аргумент в   |
|                                    | TO_STR(abcd)                       | двойные кавычки: `"abcd"`.          |
+------------------------------------+------------------------------------+-------------------------------------+
| 5. Оператор склейки токенов (##)   | #define CONCAT(a, b) a ## b        | Склеивает два куска текста в один:  |
|                                    | CONCAT(val, 1)                     | превратится в имя переменной `val1` |
+------------------------------------+------------------------------------+-------------------------------------+

Примеры:
    #define MAKE_VAR(name, num) name ## _ ## num
    MAKE_VAR(speed, 1) = 100;
    Итог: speed_1 = 100; 


---
Не забывать про скобки - как защита:
    Пример: ((x) ? "true" : "false")
    - Скобки вокруг (x) защищают от конфликта приоритетов операторов (если x => a && b)
    - Внешние общие скобки защищают всё выражение целиком, чтобы встраивать его в формулы и условия.

---
Сложные случаи:
    - Ловушка двойного вычисления (Side Effects) - выражение с ++/-- выполнится несколько раз
        #define SQUARE(x) ((x) * (x))
        int a = 2
        int a = SQUARE(i++);  // превратится: ((i++) * (i++)) - > вернет 6, а не 4 (инкременты - боль, не делать)
    - Идиома do { ... } while(0) - если пишем макро, который должен встать под тело if, то надо обернуть его в идиому.

Создание, область видимости и удаление макросов
    ВАЖНО! Объявлять макро можно (НО НЕ НУЖНО) в любом месте программы! Работать начнет строго НИЖЕ по тексту.
    Макросы полностью игнорируют правила областей видимости языка (не подчиняются фигурным скобкам), поэтому:
    Директива #undef - стирает макрос из памяти препроцессора - после нее использовать макрос будет больше нельзя.
        void Сalculate(void) {
            #define LOCAL_LIMIT 255 // можно, но плохо - если не закрыть, отравит весь код ниже
            // Здесь LOCAL_LIMIT доступен
            #undef LOCAL_LIMIT // начиная со след.строки макрос LOCAL_LIMIT здесь уже не существует
        }

Внутрь двойных кавычек (строка) ПреПрц не заглядывает!
#define VERSION "1.0.4"
printf("Текущая версия: VERSION\n");  // ОШИБКА ЛОГИКИ: напечатает "Текущая версия: VERSION"
printf("Текущая версия: %s\n", VERSION); // ПРАВИЛЬНО: напечатает "Текущая версия: 1.0.4"

Вложенность макросов
    Обрабатываются рекурсивно за несколько проходов. Дойдя до вложен.макроса ПреПрцр переходит к его подстановке.
Простой пример:
    #define BASE_CLOCK    16000000          // Частота процессора (16 МГц)
    #define PRESCALER     4                 // Делитель частоты
    #define SYSTEM_CLOCK  (BASE_CLOCK / PRESCALER) // Макрос содержит два других макроса
Сложный пример:
    #define BOOL_STR(x)      ((x) ? "true" : "false")
    #define LOG_STATUS(code)  printf("Connected: %s\n", BOOL_STR(code == 200))
Запрет на саморекурсию
    Если во время развертывания ПреПрц встретит этот же макрос, то оставляет текст как есть.
        // Попытка создать бесконечный макрос
        #define BLACK WHITE
        #define WHITE BLACK

        int color = WHITE; // заменит BLACK -----> WHITE --x--> BLACK. Блэк уже был, второй замены (на BLACK) не будет!.

СТРОКА
    Просто последовательный массив байт в памяти, который заканчивается специальным маркером — нуль-терминатором НТ (\0).

Два способа объявления:
    1) Строковый литерал (char* str = "Hello";)
        Компр берет строку "Hello", добавляет к ней \0 и записывает её в сегмент данных (Read-Only Data / .rodata) 
        внутри бинарника.
        Переменная str — это просто указатель (адрес), который смотрит на эту ячейку.
        Эту строку нельзя изменять!
        Правильный тон в Си: писать const char* str = "Hello";

    2) Массив в стеке (char str[] = "Hello";)
        При запуске функции в стеке выделяется честный массив из 6 байт (5букв + НТ).
        Можно изменять как угодно.
        Умрет при выходе из области видимости.

КЕЙС!
При сборке строки вручную, обязательно проставить НТ!

Варианты создания:
1. Автоматический размер + инициализация
    char str[] = "asdf";
• Размер буфера: 5 байт
• Содержимое: Строка "asdf\0"
• Можно редактировать символы или даже укоротить строку: str[2] = '\0';
• Можно двигать нуль-терминатор назад и вперед, главное — не выходить за пределы изначальных 5 байт.
    ДЛЯ ИСТОРИИ: логичнее было бы char[] str = "asdf", но Ритчи уперся бараном, т.к. "как используется, так и объявляем".

2. Фиксированный размер БЕЗ инициализации (Мусор в памяти)
    char str[10];
• Размер буфера: 10 байт.
• Содержимое: Случайный мусор.
• Чистая заготовка (буфер) под будущую запись.

3. Фиксированный размер + зануление всей памяти
    char str[10] = {0}; 
    // или альтернативный вариант:
    char str[10] = "";
• Размер буфера: 10 байт.
• Содержимое: Все 10 байт гарантированно заполнены нулями (\0).
• Самый безопасный способ создания буфера - что ни запиши (<10байт), в конце всегда будет \0.

4. Фиксированный размер + частичная инициализация
    char str[10] = "asdf";
• Размер буфера: 10 байт.
• Содержимое: Первые 4 байта — 'a','s','d','f', 5-й байт — '\0'. Все оставшиеся 5 байт заполнены нулями.
• есть строка по умолчанию, но оставляем в буфере запас места, чтобы позже дописать туда что-то еще.

Опасный экзотический вариант: VLA (Массив переменной длины)
    int n = 20; // или значение пришло из аргументов функции
    char str[n]; 
• Размер массива определяется динамически прямо во время работы программы.
• ОПАСНО. Уронить по SOF как не фиг делать. В embed часто запрещено.

---
Присвоение строк
    После объявления строки на стеке просто присвоить нельзя.
        char str[10];
        str = "asdf"; // ОШИБКА КОМПИЛЯЦИИ! Имя массива — это константный указатель.

Записать текст в созданный массив можно только через функции копирования памяти:
    snprintf(str, sizeof(str), "asdf");
    strcpy(str_dest, str_src); // устарела, опасная, не проверяет ничего, тупо переносит
    strncpy(str, "asdf", sizeof(str));

Функция вывода PRINTF (print formatted)

Самое веселое отличие - в Си НЕТ ТИПОБЕЗОПАСНОСТИ при выводе на экран, 
    вся работа printf строится на ручном указании типов через спецификаторы формата.

Заголовок: stdio.h

    // (1) Выводит результат в стандартный поток вывода stdout.
    int printf( const char *restrict format, ... );

    // (2) Записывает результат в указанный поток вывода stream.
    int fprintf( FILE *restrict stream, const char *restrict format, ... );

    // (3) Записывает результат в текстовый буфер (строку) buffer. 
    // Внимание: поведение не определено, если размер буфера меньше записываемой строки.
    // ВАЖНО! В современной разработке использовать sprintf категорически запрещено! ОПАСЕН. Нужен для обр.совм.
    int sprintf( char *restrict buffer, const char *restrict format, ... );

    // (4) Безопасная версия sprintf. Записывает не более (bufsz - 1) символов.
    // Результат всегда завершается нуль-символом '\0' (если bufsz > 0).
    int snprintf( char *restrict buffer, size_t bufsz, const char *restrict format, ... );

---
Возвращаемое значение
    • printf и fprintf: Возвращают количество успешно записанных символов или отрицательное значение в случае ошибки.
    • sprintf: Возвращает количество записанных символов в буфер (не считая завершающий \0).
    • snprintf: Возвращает количество символов, которое БЫЛО БЫ записано, если бы размер буфера был неограниченным 
        (не считая \0). Это позволяет узнать точный размер буфера, необходимый для записи.

---
Строка форматирования (format) - состоит из обычных символов (которые копируются в вывод как есть) 
    и спецификаторов преобразования, начинающихся со знака %.

    %[флаги][ширина][.точность][модификатор_длины]<тип>

1. Флаги (необязательные)
    • - : Выравнивание по левому краю (по умолчанию — по правому).
    • + : Перед знаком неотрицательного числа всегда ставить + (для знаковых типов).
    • Пробел : Если число неотрицательное, вместо знака ставится пробел (игнорируется, если задан +).
    • 0 : Заполнять ширину поля ведущими нулями вместо пробелов.
    • # : «Альтернативная форма» вывода:
        • Для %x или %X — добавляет префикс 0x или 0X (если число не ноль).
        • Для %o — увеличивает точность, чтобы первый символ был 0.
        • Для чисел с плавающей точкой — всегда выводит десятичную точку.

2. Минимальная ширина поля
    Задает мин число символов для вывода. Если результат короче, он дополняется пробелами (или нулями при флаге 0). 
    Если вместо числа указана звездочка *, ширина передается как дополнительный аргумент типа int перед значением.
        int width = 10;
        printf("CPU 1: %*.2f\n", width, cpu_low);

3. Точность (.точность) - Задается в виде точки и числа (или .*, где значение берется из аргументов):
    • Для целых чисел: Минимальное количество выводимых цифр (дописывает ведущие нули).
    • Для чисел с плавающей точкой: Количество знаков после запятой.
    • Для строк (%s): Максимальное количество выводимых символов (строка обрезается).

4. Модификаторы длины аргумента - Определяют точный размер типа данных, переданного в функцию:
    • h : аргумент приводится к short или unsigned short.
    • hh : аргумент приводится к signed char или unsigned char (с C99).
    • l : для целых — long / unsigned long; для строк — wchar_t*.
    • ll : long long / unsigned long long (с C99).
    • z : тип size_t (с C99).
    • t : тип ptrdiff_t (с C99).

---
Спецификаторы типа (Символ преобразования) <тип>

Символьные и текстовые типы
    • %c : Вывод одного символа (тип int, автоматически преобразуемый в unsigned char).
    • %s : Вывод строки (указатель char*) до первого нуль-символа \0.
    • %p : Вывод указателя (тип void*). Формат вывода зависит от реализации ОС (обычно шестнадцатеричный).
    • %% : Вывод самого знака процента %.

Пример: int* px = &x;
        printf("Hello, %p, World!\n", px);

Целые числа
    • %d или %i : Знаковое целое число в десятичном формате.
    • %u : Беззнаковое целое число в десятичном формате.
    • %o : Беззнаковое число в восьмеричном формате.
    • %x или %X : Беззнаковое число в шестнадцатеричном формате (abcdef или ABCDEF).
    • %b : Беззнаковое число в двоичном формате (появился в новом стандарте C23).

Числа с плавающей точкой (double / float)
• %f / %F : Десятичное представление числа вида [-]ddd.ddd (по умолчанию 6 знаков после точки).
• %e / %E : Экспоненциальная форма записи вида [-]d.ddde±dd.
• %g / %G : Автоматический выбор наиболее короткого и красивого формата (%f или %e).

Специфические системные
• %n : Особый спецификатор. Он не выводит данные, а записывает количество символов, выведенных до текущего момента, 
    в переменную типа int*, переданную как аргумент.
        int* paa;
        printf("ASDF asdf%n\n", paa);
        printf("%d\n", *paa);

---
Остальные варианты:
    +-----------+-----------------------------+------------------------+---------------+
    | Функция   | Куда отправляет результат?  | Защита от переполнения | Безопасность  |
    +-----------+-----------------------------+------------------------+---------------+
    | fprintf   | В файл (FILE*) или потоки   | Не применимо           | Безопасно     |
    |           | (stderr / stdout)           | (пишет в поток)        |               |
    +-----------+-----------------------------+------------------------+---------------+
    | sprintf   | В массив символов (char*)   | Нет (ломает память)    | Опасно!!!     |
    +-----------+-----------------------------+------------------------+---------------+
    | snprintf  | В массив символов (char*)   | Да (контроль размера)  | Безопасно     |
    +-----------+-----------------------------+------------------------+---------------+

ВАЖНО!
1) Не использовать sprintf в серьезных проектах. Если строка окажется длиннее буфера, произойдет выход за границы 
    памяти (Buffer Overflow). Юзать безопасный snprintf.
2) Перекрытие буферов: Запрет передавать один и тот же буфер в качестве приемника и аргумента одновременно (UB):
    > sprintf(buf, "%s и еще текст", buf);
3) Динамический расчет размера: Вызов snprintf(NULL, 0, fmt, ...) вернет количество байт, необходимых для строки. 
    Это стандартный трюк для динамического выделения памяти:
        int size = snprintf(NULL, 0, "Число: %d", 12345);
        char *buf = malloc(size + 1); // +1 для нуль-терминатора
        snprintf(buf, size + 1, "Число: %d", 12345);

Примеры ошибок

ОШИБКА - Перепутал спецификатор:
    printf решит, что число 25 — это адрес в памяти (указатель), 
    полезет по адресу 0x00000019 искать строку и упадет в Segmentation Fault.
        int age = 25;
        printf("Мне %s лет\n", age); 

ОШИБКА - Не додал аргументов:
    // Для Y аргумента нет. printf все равно полезет в стек
    // и прочитает следующие 4 байта — там окажется случайный мусор, который лежал в памяти.
        printf("Координаты: X=%d, Y=%d\n", 10);

ОШИБКА - Вывод строк без \0:
    printf напечатает "Том", а дальше пойдет печатать 
    все байты оперативки подряд, пока случайно не наткнется на байт 0x00.
        char name[3] = {'Т', 'о', 'м'}; // Нет нулевого байта в конце!
        printf("Имя: %s\n", name);
